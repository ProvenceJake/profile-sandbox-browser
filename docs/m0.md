# M0 第一轮本机实测

2026-11-23，macOS 15.8.3 arm64，Google Chrome 158.0.8127.36（headless），Mihomo v1.19.33，Node.js v26.13.0。运行入口为 `node probes/m0.mjs`。

| 项目 | 实测结果 |
| --- | --- |
| 槽位分配 | 五个 mixed listener 初始化时的 selector 均为 REJECT。分别选择五个本地 HTTP 节点后，同时发出的请求收到各自的节点标记。 |
| 连接切换 | Unix socket 控制器返回的连接记录包含 `metadata.inboundName`。切换第一个槽位、按该字段关闭旧隧道后，新请求收到新节点标记，第二个槽位已建立的隧道仍能回显数据。 |
| 五个浏览器的隔离 | 五个 Chrome 进程同时存活，各自使用独立 user-data-dir。同源页面写入五个标记，Cookie、localStorage、IndexedDB 和 CacheStorage 各自只读回自己的值。 |
| 环境一致性 | 东京、巴黎、柏林、圣保罗、纽约五组配置均通过。主页面、同源 iframe、弹窗、Dedicated Worker、Shared Worker、Service Worker 的时区、首选语言和语言列表都与配置一致。服务器观察到的 Accept-Language 首项也一致。 |
| 代理故障 | 对测试 Mihomo 发送 SIGKILL 后，五个浏览器请求同源回显页面均失败。同一时刻独立直连请求仍收到页面响应。 |
| CDP 管道 | 在子进程的 fd 3/4 上读写以零字节分隔的 JSON 成功。依次关闭各自的管道后，五个浏览器主进程均在 3 秒观察窗内退出。 |

## 对后续实现的影响

单 Profile 闭环可采用固定槽位和 Unix socket 控制器。切换时还需要处理真实浏览器同时建立新连接的情况。本轮验证在已知旧连接上操作，正式实现需在验证新出口前暂停业务流量。

在上述运行时组合上，启动时设置 TZ、语言参数和 Preferences 已能覆盖实际测过的六种上下文。正式运行时仍需检查启动后自检、地理位置授权、坐标覆盖以及 CDP 各类 target 的能力。Node 的管道验证覆盖了浏览器端协议行为；Rust 的文件描述符映射、异常退出和孤儿回收还需独立验证。

模拟节点仅在回环地址返回标记。真实节点出口 IP、权威 DNS、WebRTC、IPv6、HTTP 网络缓存隔离、原生窗口和性能矩阵均待验证。测试页面使用的 CacheStorage 属于 Web 缓存 API。M0 尚未达到完整退出门槛。

相关协议见 [Mihomo 控制器 API](https://wiki.metacubex.one/api/) 和 [Chrome DevTools Target 协议](https://chromedevtools.github.io/devtools-protocol/tot/Target/)。
