# 桌面版本 0.9.0 验收记录

2026-11-23，macOS 15.8.3，Apple Silicon。测试使用 Chrome 158.0.8127.36 和随应用分发的 Mihomo 1.19.33。

| 范围 | 结果 |
| --- | --- |
| 桌面操作 | 从管理窗口录入本机 HTTP 代理，创建自动环境 Profile，实际下载城市库并从真实公网出口启动 Chrome；停止后运行槽位回到零。 |
| 五路并发 | 正式 Rust 管理器启动五个浏览器，用五个独立的本地代理标记核对路由。第六个启动请求被拒绝。 |
| 数据隔离 | 五个浏览器访问同一来源，Cookie、localStorage、IndexedDB、CacheStorage 和 HTTP 缓存读回各自的标记。 |
| 环境一致性 | 两次出口回显一致，请求头首选语言与配置一致。启动检查覆盖主页面和 Worker，M0 回归额外覆盖 iframe、弹窗、Shared Worker、Service Worker。 |
| 节点与订阅 | 从本机 HTTP 夹具导入并刷新 Clash 订阅；保留同名节点 ID。切换同地区节点保留浏览器进程；地区变化等待确认；来源更新移除已绑定节点后，受影响的浏览器停止。 |
| 本机网络检查 | 一个随机 .invalid 目标域名能经代理访问夹具。启用 WebRTC 数据通道并指定本地 STUN 端口，在五秒观察窗内未发现非中继 ICE 候选或送达该端口的 UDP 数据报。 |
| 断网和恢复 | 结束代理进程时，浏览器无法访问可直接连接的 IPv4、IPv6 回环来源。恢复之后重新核验五个出口。强制结束一次性测试管理器后，其 Chrome 主进程和 Mihomo 均退出。 |
| 数据与监控 | 进程树的物理内存、CPU、标签页数和启动记录写入 SQLite；Profile 配置复制、移入回收目录、恢复、永久清除均有集成测试。 |
| 运行时安装 | 下载的 Chrome for Testing 压缩包仅含链接器临时签名。实现改用固定哈希的 Google Chrome Stable DMG。实测通过只读挂载、复制、卸载、版本核对和 Google 签名验证。 |

真实出口测试使用本机现有代理。并发与故障测试使用可控制的本地代理，避免把个人节点凭据、订阅或出口地址写入仓库。启动时钟从正式启动流程开始，到第一个工作标签页加载事件结束，首次依赖下载单列为准备过程。

完整发布验收还需在受控公网权威 DNS 和原生双栈网络核对解析来源与 IPv6 公网流量，按规划执行轻量、普通、重型页面的长时间性能矩阵，并在 Developer ID 签名公证后验证分发。因此本版本保留 GitHub 预发布标记。

## 0.9.1 的语言和时间复核

在本机以 0.9.0 的地区参数启动 Chrome 时，东京与巴黎 Profile 的网页首选语言和请求头分别为日语和法语，默认日期和数字格式都返回 zh-CN。此前的语言检查没有覆盖这两个接口。

0.9.1 在浏览器放行新页面和 Worker 前下发 ICU 地区设置，并将 Intl.DateTimeFormat 与 Intl.NumberFormat 的默认 locale 纳入启动自检。正式 Rust 后端使用五组地区配置复测，包括 fr-CA。每组均检查了主页面、同站 iframe、跨站 iframe 的首段脚本、弹窗、Dedicated Worker、Shared Worker、Service Worker。

网页中的 Date.now() 使用 Mac 的实际时钟。指定同一个 UTC 时刻时，本地小时数按 Profile 时区和夏令时换算。管理器的启动记录也使用系统时间。上述验证范围是网页可观测的这些接口，未对 Chrome 的每一次系统调用进行审计。
